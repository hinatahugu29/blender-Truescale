最終更新 2026-09-21

**何を踏みやすいか**を知るためのもの。
調べたことの記録は [レビューメモ](レビューメモ.md) にある。

## 0. 現状

| | |
|---|---|
| 名称 | Truescale（パッケージ `truescale`） |
| 出自 | 知人が生成AIで作った2つのアドオン。2026-09 に全面委任を受け、統合した |
| 構成 | 1アドオン。パネルで「型紙」と「三面図」を分ける |
| 対象 | Blender 5.2 以上（下限を下げられるかは未検証） |
| 規模 | 67ファイル / 約 21,000 行 |
| テスト | `test_pure.py` 71件、`test_headless.py` 79件 |

### 型紙側と三面図側は、ほぼ別のアドオン

三面図側がパッケージの外から読んでいるのは `debug`、`core.units`、`core.paper`、
`export.png` の4つだけ。逆に型紙側から三面図側への参照は無い。

**一方から他方へ流れるものも無い。** 三面図を出してから型紙にする、という順序は
存在せず、利用者はどちらかを使う。共有しているのは実質サイドバーのタブだけである。

| | 型紙（Unfold） | 三面図（Draft） |
|---|---|---|
| 縮尺 | **絶対に変えない** | 落とす（1:2、1:5…） |
| 出口 | ベクタ（PDFの線） | ラスタ（PNGのピクセル） |
| 作り方 | UV から幾何を計算 | **ビューポートを撮る** |
| 収まらないとき | 分割して複数枚 | 縮尺を落とす |
| ビューの状態 | 触らない | **書き換えて、戻す** |

最後の行が三面図側の難しさのほぼ全部。詳しくは 3-10。

## 1. コードの地図

登録だけが `truescale/unfold/__init__.py` と `truescale/draft/__init__.py` にある。
**中身はそこには無い。** 探すときは下の表から入る。

各ファイルの冒頭に、**なぜそうなっているか**を書いてある。直す前に読むこと。

## 2. 作業の進め方

```bash
tools/run_tests.cmd
```

静的チェック → Blender非依存の単体テスト → ヘッドレステスト、の順に流れる。
**変更のたびに通すこと。**

### 検査ツールが見るもの（`tools/check_addon.py`）

| | |
|---|---|
| 1 | パネルが参照しているが実装されていないオペレータ |
| 2 | 実装されているがどこからも呼ばれていないオペレータ |
| 3 | 定義されているが `classes` に登録されていないクラス |
| 4 | 参照されているが register されていない Scene プロパティ |
| 5 | register されているが unregister で消されないプロパティ |
| 6 | register されているがどこからも参照されていないプロパティ |
| 7 | どこからも呼ばれていないモジュール直下の関数 |
| 8 | **未定義のまま読まれている名前**（実行時に NameError） |
| 9 | **ローカル変数が同名の関数を隠している**（UnboundLocalError） |
| 10 | **`@persistent` が付いていないハンドラ** |
| 11 | **return などの後ろに置かれて実行されないコード** |
| 12 | くだけた言い回し（利用者が読む文章に混ざったもの） |
| 13 | 用語の揺れ（縮率 → 縮尺 など） |
| 14 | **ミリの値に `unit='LENGTH'`**（画面には「8 m」と出る） |
| 15 | **シーンの Unit Scale の直読み**（`core.units` を通していない） |

8〜11、14、15 は実際に事故を起こした型。**新しい検査を足したら、
壊した版で検出することを必ず確かめる。** 10番と11番は、それをやらずに
書いて効かなかったことがある。

### その他の道具

| | |
|---|---|
| `tools/deps.py` | 関数の依存を測る。**分割の順番はこれで決める**（勘だと循環する） |
| `tools/test_pure.py` | bpy 不要の単体テスト。速い |
| `tools/test_headless.py` | Blender をヘッドレスで起動して実操作を試す |
| `tools/build.py` | 配布用 ZIP を作る |
| `tools/build_docs.py` | `docs/*.md` から HTML マニュアルを作る |
| `tools/audit_settings.py` | 設定ごとの描画コストを実測する |

| `tools/measure_depsgraph.py` | depsgraph ハンドラのコストを測る |
| `tools/dump_state.py` | 状態が今どうなっているかを出す |

## 3. 踏みやすい落とし穴

### 3-0. 同じ値を2箇所で作らない ← いちばん多い

このプロジェクトで**繰り返し出た唯一の型**。見つかっただけで7回ある。

| 何が2つあったか | どう壊れたか |
|---|---|
| 印の色の決め方 | 手で置いた印だけ色が追従しない |
| `RESET_ON_LOAD` のキー | 手動レイアウトのフラグが解除されない |
| 使える紙の大きさ | 用紙ガイドは収まると言い、刷るとはみ出す |
| 用紙の表（3箇所） | 三面図側にだけ A5 と B判が無い |
| 実寸の換算 | 型紙 40mm / 三面図 1000mm。同じファイルで 25 倍 |
| 寸法の文字の置き場所 | 画面では見える文字が PNG で切れる |
| 面図ごとの軸の表（5箇所） | 画面と刷ったもので寸法の位置が変わる |

どれも**片方だけ直せば黙ってずれる**。しかも多くは刷ってみるまで分からない。

**足す前に「同じことを決めている場所が他に無いか」を探すこと。**
見つけたら、表なら1つに寄せる。計算なら関数に出す。
どうしても2箇所要るなら、**突き合わせるテストを書く**
（`test_sheet_and_screen_place_dimensions_alike` が例）。

### 3-1. 描画の中の例外は握り潰される

描画ハンドラは全体が `try/except` に包まれている。落ちると画面が真っ暗に
なるためで、これ自体は正しい。ただし **`NameError` も同じように消える**ので、
「エラーも出ないがただ描かれない」という形になる。

実際、分割で参照を取り残したとき、島のハイライトと配置の下描きが**黙って
出なくなっていた**。検査ツールの 8番はこのために足した。

原因を追うときは環境変数 `TRUESCALE_DEBUG` を立てる。`debug.swallowed()` が
場所とトレースを出す。

### 3-2. キャッシュのキーに設定を入れ忘れる

`marking/compute.py` のキャッシュは、キーに含まれない設定を変えても効かない。
**「値を変えたのに反映されない」はほぼこれ。**

逆に、キャッシュを捨てる（`invalidate_layout_cache`）と epoch が進んで**全部**
作り直しになる。スライダーをドラッグすると毎フレームそれが走り、体感が重くなる。

正しいのは「キーに入れたうえで再描画だけにする」。`props.py` の
`_pattern_redraw_only_updated` を使う。

### 3-3. `matrix_world` をキャッシュキーに入れない

入れるとオブジェクトを G で動かすたびにキーが変わり、島の解析と配置探索が
毎フレーム走る。**「移動したときだけ極端に重い」**の正体だった。

ローカル空間で計算してキャッシュし、ワールド変換はキャッシュの外で掛ける。

### 3-4. ハンドラには `@persistent` が要る

無いと、Blender は `.blend` を読み込むときにハンドラ一覧から外す。
初期化や追従が「保存して開き直すと効かない」形で壊れる。

### 3-5. 状態の置き場を間違えない

| 置き場 | 用途 |
|---|---|
| 登録プロパティ（`bpy.props`） | UIに出す設定。型と既定値があり、unregister で消える |
| `scene["..."]`（`core/session.py`） | 作業中の状態。`.blend` に残るが、開くときに初期化する |
| モジュール直下の辞書（`marking/interact.py`） | 操作中だけの状態。Blender を閉じれば消える |
| Object のカスタムプロパティ | 注記や対応表。型紙を作り直しても残す |

**`core/session.py` にキーを足したら、`RESET_ON_LOAD` にも入れるか判断すること。**

「作り直しても残したいもの」は、**元メッシュ**の側に持たせる。展開後の番号で
覚えると、型紙を作り直した瞬間に失われる（糊代を消した記録がこれ）。

### 3-6. 移行用の別名は必ず消す

分割の途中で「既存の呼び出しをそのまま動かす」ための別名を置くことがある。
**移し終えたら全部消す。** 残すと、そのファイルがまだ全部を持っているように
見え、次に読む人が誤解する。

### 3-7. 消す前に `tools/` も見る

検査ツールの 7番（未使用の関数）は `truescale/` の中しか見ない。
**テストだけが使っている関数は「未使用」と出る。** 実際にそれを信じて消し、
テストを壊した。

### 3-8. 旧プレフィクスの文字列は書き換えない

`draft/keys.py` の `LEGACY_*` は、過去のバージョンが実際に残していった文字列。
後始末のためだけに持っている。今の名前に合わせて一括置換すると、古いファイルに
残ったハンドラを外せなくなる。

### 3-9. 画面に出す数字が嘘をつく形に気をつける

いちばん質の悪い不具合。利用者が自力で気付けない。

- はがきに 100mm の目盛りを描いて、84mm に切られていた
- ミリの設定に `unit='LENGTH'` が付いていて、`1` が「1 m」と表示されていた
- 合わせの印を受け持ち範囲の四隅に置いていた（重ねると必ずずれる）

**「画面に出る数字・目盛り・目印は、実物と一致しているか」を疑うこと。**
検査ツールの 14番はこのために足した。

### 3-10. 三面図側は「変える → 撮る → 戻す」

ビューポートを撮るので、撮る前に背景を白にし、オーバーレイを消し、視点を
動かし、**終わったら全部戻さなければいけない**。

`viewstate.export_view`（コンテキストマネージャ）の中でだけ変わり、抜けるときに
必ず戻る形にしてある。**書き換える設定を足すときは、`EXPORT_SCENE_FLAGS` にも
足すこと。** 足し忘れは `test_export_restores_every_flag_it_changes` が
実際のコードを読んで捕まえる。

### 3-11. インストール先と原本は別物

Blender が読むのは以下のコピー。

```
C:\Users\hinat\AppData\Roaming\Blender Foundation\Blender\5.2\extensions\user_default\truescale\
```

`tools/build.py` で ZIP を作り、Blender 側で入れ直すこと。

## 4. テストが無い領域

ヘッドレスでは動かせないものは、手で確認するしかない。

- 実際のビューポート描画
- modal 操作（印を置く道具）
- 書き出しの見た目
- **三面図の撮影と切り抜き**（実際の 3D ビュー領域が要る）

**ここを触ったら必ず実機で押すこと。** 特に三面図の書き出しは、
「書き出したあとビューが元へ戻るか」「画像に N パネルが写らないか」を
毎回確かめる。

## 5. 残っている課題

### 機能

| | 内容 |
|---|---|
| U-05 | 用紙に入らないときに、どうすれば入るかを出す（一部実装済み） |
| U-07 | UV展開の歪み率表示（計算済みの値を捨てている） |
| — | 糊代を付ける側を手で入れ替える（いまは消すだけ） |
| — | 糊代を入れたときに島の間隔を自動で広げる |
| — | 元モデルの面に島ID（A/B/C）を出す。型紙と三面図が唯一つながりうる点 |

### 整理

- パネルに出していないオペレータは `select_unfold_source` のみ。
  なめらか仕上げの扱いが決まったら判断する
- `blender_version_min = "5.2.0"` を 4.2 まで下げられるかは未検証
- 三面図側の文字描画（独自ビットマップフォント）は型紙側と統合できない。
  画面を撮る以上、出てくるのは画像なので、輪郭線方式は使えない。**本当の境界**
